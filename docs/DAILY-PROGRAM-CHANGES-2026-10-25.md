# Daily program and controlled schedule changes
Portal home now shows all active activities for today (up to 30 with a link to the full list), including earlier unfinished activities, current/upcoming labels, meeting links and edit/review links. Completed/cancelled entries remain in a disclosure. Calendar snapshot timing and device-reminder state are explicit.
Reminders support a single lead or staggered chosen lead / five minutes / start time. Zero remains off. Existing records inherit the saved preference; the global preference is changed only through the owner form. Unique item/version/stage/device records prevent repeat pushes. A delayed worker chooses only the latest due stage, marks older stages superseded and applies a five-minute grace rather than sending a catch-up burst. Quiet hours and opted-in devices remain required. Routine imports retain reminders off.
Owner booking rescheduling chooses live verified available slots, preserves duration, confirmation status and frozen reply mailbox, and requires a reason and explicit notification confirmation. Optimistic version checking is inside the reservation lock. Public rescheduling also records a reason. Existing calendar event IDs are retained; no duplicate event is created.
Owned Google event edits add date/time changes and inclusive all-day date ranges, with ETag checks and existing event-edit scope. A series master must be changed in the source app; individual occurrences may be updated. Read-only Outlook/Zoom/Webex connections are not silently expanded. Date/time changes in local programs preserve history and may explicitly queue notices to their saved recipients. Cancellation and lateness retain reasons.
Tests use isolated clocks/databases and synthetic device transports. No live meeting was moved or cancelled.
