# Booking senders and platform options
Booking email identities are a separate per-account Google send-only OAuth grant (gmail.send plus identity). Existing calendar/read/draft permissions are unchanged. Each account must be connected and explicitly confirmed in /write/booking-mailboxes. Public links carry an opaque host identity; submitted bookings freeze the verified sender email/id/label. Receipts and all service notices use that account, including From and Reply-To. Failure holds delivery for review; there is no fallback to another sender. Existing bookings retain the website sender. The current Google calendar organizer remains independent and is disclosed in settings; this release does not authorize calendar writes for each mailbox.
Authorized redirect URI: https://www.waithakandegwa.com/write/connections/callback/google_booking_mail
No account was authorized and no real email was sent as part of source implementation. The owner must grant send access for each mailbox; connected calendars alone are insufficient.
Social options are normalized, saved and frozen with the approved revision, shown in saved review, and either transmitted by the implemented adapter or block automatic approval with an assisted-delivery instruction. Instagram single-image direct posts carry location_id and bounded username/x/y user_tags. Facebook Page direct carries place; professional profiles stay assisted. X direct carries geo.place_id; native account settings must permit it. YouTube direct supports keyword tags and metadata language. Location labels, native mentions, collaborators, audience choices and app-only music/stickers/polls are stored as an explicit assisted checklist, not silently discarded by direct/Buffer delivery. These features depend on platform eligibility and permissions.
Culture is added idempotently as a My Thoughts category/topic. No article is fabricated or published. The deployment hook is a focused data insert that preserves any existing Culture record.
