# Private reports, booking review and weekly routines

Public pages no longer inherit a QR reference block. Existing document/report/payment record references are retained for printing or saving as PDF; QR symbols are hidden on screen and shown in print. Private report QR destinations require authentication and contain record IDs, never access tokens.

Private Notes & reports supports typed/mobile keyboard dictation notes, explicit selected-provider AI drafting, editing, version-specific human review, a print/PDF report, and explicit single-recipient email delivery through the existing designed email and scoped outbox. WhatsApp opens a reviewed draft in the app for recipient selection and final send; long reports can be attached as PDFs there. No WhatsApp API delivery or inbox receipt is claimed.

The daily planner adds a bounded weekly routine template (days, local times, title and activity). Overnight sleep ends next morning; DST gaps/ambiguities fail validation. Apply a template once per Monday-based week, atomically, without modifying meetings or creating invitations. Routines have no default reminders to avoid a notification burst. Existing daily editing and overlap warnings apply. The weekly view includes all saved program/calendar/booking entries. The example routine is illustrative and is never applied automatically.

Google Maps input explicitly selects search/address or latitude/longitude. Only the selected mode is retained; Maps search/directions open externally. No live geocoder or location permission is implied.

Booking now offers only live-verified slots. The former preferred-time contact fallback is removed. All new bookings require approval regardless of older instant-confirmation settings. Optional one-file PDF/JPEG/PNG uploads (4 MB) are MIME checked, stored through the existing private S3/local store, and accessed only by the booking owner. A document needs visitor consent for Google Gemini analysis. Binary integrity is checked before analysis. Attachments never become public media assets.

Agenda-only requests receive a factual supplied-information briefing. Document requests wait for an AI briefing generated by the independently opted-in booking worker; failures/interrupted work remain for manual host document review and report completion. No automatic retry loop or AI acceptance occurs. A report is required before calendar confirmation. Owner review email contains the briefing and YES/NO links to an authenticated confirmation page; GET links never mutate a booking. Dashboard decisions recheck calendar availability under the existing reservation lock. Email-reply parsing is not implemented.

Booking enablement additionally checks the required calendars live. Provider authorization, Workspace status and notification readiness remain external prerequisites; no required calendar is silently removed. No existing legacy queues are enabled by this release. No schema changes or new paid infrastructure.

Validation: PHP/MySQL CI includes new pure routine/Maps/briefing policies, database ownership/version/report-review gates and routine duplicate prevention, plus real HTTP notes/consent/PDF-view/email-consent checks. No real meetings, reports or recipient messages are created in production acceptance.
